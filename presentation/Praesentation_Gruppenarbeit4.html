Was war unsere Aufgabe?

Ausgangssituation

Die Müller & Partner GmbH möchte ein internes Intranet für ihre Mitarbeiter bereitstellen. Informationen und Ankündigungen sollen zentral veröffentlicht werden. Der Server soll remote administriert werden können.

Kundenauftrag

Installation und Konfiguration von:

  • 🌍 Apache Webserver (HTTP, Port 80)
  • 🔒 OpenSSH Server (Port 22)
  • 🛡️ UFW Firewall (nur SSH + HTTP)

Eingerichtete Dienste

🌍

Apache2 Webserver

Bereitstellung der internen Intranet-Webseite. Erreichbar auf Port 80 (HTTP). Inhalte unter /var/www/html/.

sudo apt install apache2
Port: 80/TCP
🔒

OpenSSH Server

Sichere Fernadministration des Servers vom Client aus. Passwort- und Schlüsselauthentifizierung. Root-Login deaktiviert.

sudo apt install openssh-server
Port: 22/TCP
🛡️

UFW Firewall

Schutz des Servers. Nur SSH (22) und HTTP (80) eingehend erlaubt. Alle anderen Ports blockiert.

sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
default: deny
Firewall-Regeln: ✅ SSH Port 22  |  ✅ HTTP Port 80  |  ❌ Alle anderen Ports

Wie wurde es umgesetzt?

Server-Konfiguration

  • 1Ubuntu Server 22.04 in VirtualBox installiert
  • 2Statische IP 172.16.40.10 via Netplan konfiguriert
  • 3OpenSSH installiert, PermitRootLogin=no, Banner erstellt
  • 4Apache2 installiert, Intranet-Webseite erstellt
  • 5UFW Firewall aktiviert: nur Port 22 + 80

Client-Konfiguration

  • 1Ubuntu Desktop in VirtualBox eingerichtet
  • 2Statische IP 172.16.40.100 konfiguriert
  • 3Server in /etc/hosts eingetragen
  • 4SSH-Verbindung zum Server hergestellt
  • 5Webseite im Browser geöffnet
# SSH-Verbindung vom Client zum Server:
ssh admin@172.16.40.10
# Webseite im Browser:
http://172.16.40.10  |  http://server.gruppe4.local

Netzwerkanalyse mit Wireshark

📡 HTTP-Analyse (Port 80)

Wireshark-Filter: tcp.port == 80


Sichtbare Pakete beim Browseraufruf:

  • TCP SYN – Verbindungsaufbau
  • HTTP GET – Browser fordert Seite an
  • HTTP 200 OK – Server antwortet
  • TCP FIN – Verbindungsabbau

🔒 SSH-Analyse (Port 22)

Wireshark-Filter: tcp.port == 22


Bei SSH sieht man:

  • TCP Handshake – Verbindungsaufbau
  • SSHv2 Banner – Protokollversion
  • Encrypted – Inhalt verschlüsselt!
  • Kein Klartext – anders als HTTP
# HTTP-Verkehr mit tcpdump beobachten:
sudo tcpdump -i enp0s3 port 80 -v
# SSH-Verkehr:
sudo tcpdump -i enp0s3 port 22 -v

Probleme & Lösungen

❌ Netzwerk-Problem

Problem: VMs können sich nicht pingen.

Lösung: VirtualBox-Netzwerkname bei BEIDEN VMs muss identisch sein: intnet-gruppe4

❌ YAML-Fehler (Netplan)

Problem: Netplan apply schlägt fehl.

Lösung: YAML ist einrückungssensitiv! Nur Spaces (keine Tabs) verwenden. Mit sudo netplan --debug apply debuggen.

❌ SSH Permission denied

Problem: Login schlägt fehl.

Lösung: PasswordAuthentication=yes in sshd_config prüfen und SSH neu starten.

❌ Webseite nicht erreichbar

Problem: Browser zeigt Fehler.

Lösung: sudo systemctl status apache2 und UFW-Regeln prüfen.

Was würden wir in der Praxis zusätzlich beachten?

🔐

HTTPS statt HTTP

TLS-Zertifikat (z.B. Let's Encrypt) für verschlüsselte Verbindungen. Kein Klartext-Transfer.

🗝️

SSH-Schlüssel

Passwortauthentifizierung deaktivieren. Nur SSH-Public-Key für Login. Sicherer gegen Brute-Force.

🚫

Fail2Ban

Automatisches Sperren von IPs nach zu vielen fehlgeschlagenen Login-Versuchen.

🔄

Automatische Updates

unattended-upgrades für Sicherheitsupdates. Regelmäßige manuelle Überprüfung.

📊

Monitoring

Log-Überwachung, Benachrichtigungen bei Fehlern. Tools: Prometheus, Grafana, Nagios.

🌐

VPN-Zugang

Fernadministration nur über VPN. SSH nicht direkt aus dem Internet erreichbar.
